# 知识库城市、区县与片段检索实现

日期：2026-10-09。状态：本地开发及离线验收完成，未部署服务器、未提交Git。用户确认的规则：城市查询覆盖所属城市笔记；明确区县时只使用可靠区县元数据；多区县攻略只返回对应片段。

## 已实现

- 收藏新增可选`sections`，每个片段包含`district_code`、`category`、`text`。整篇仍保留必填地级市、原文和原有类别。区县编码和原文片段由用户在编辑器明确选择/填写，没有用LLM自动生成“已确认”标签。
- 城市查询涵盖该城市的已标片段与未标注旧笔记。区县查询排除所有未标区县内容，不从正文地名猜归属，不回退全城。
- 一篇通用旅行攻略可以把长乐段标为美食、鼓楼段标为景点；推荐美食时按片段类别过滤，不把整篇攻略的类别当作每个片段的类别。
- 校验区县属于所选城市、片段是原文的唯一非空连续摘录、片段之间不重叠、数量不超过32。修改正文或城市导致元数据失效时拒绝保存，要求同步修改或清空片段。
- 返回区县编码和原文起点`source_start`，便于溯源；偏移按Python Unicode字符计数，不由Android的UTF-16下标生成。
- `福州长乐`、`福州市长乐区`、唯一的`长乐区`可以解析；多城市同名的`鼓楼区`不能猜测。直辖市与省直管县级市继续支持。区县范围不改变旅行记录的地级市选择器。
- 推荐调用携带food类别；规划同时需要两类，保留混合片段。旧`city＋preferences`入口仍兼容，但不代表新调用链的类别参数。
- 移除先取最新200篇再过滤的候选截断，按当前账号与城市流式读取、逐片段筛选，只保留前5个候选；正文上下文总计800字符，每片最多240字符。

当前采用项目2023行政区划数据统一验证城市归属、区县选择和检索。未新增高德网络调用；数据更新仍需统一更新版本，不能宣称与高德实时一致。

## Android使用方式

旅行收藏→添加/编辑→选择城市→填写原文→“＋添加范围片段”：

1. 输入区县名并选择服务器返回的区县。
2. 选择该片段的类别，例如美食攻略。
3. 从正文复制对应区域内容到片段框。
4. 多区县内容分开添加；不用区县限制的片段可以选择“不限定区县”。

若片段不在正文或正文修改后不再匹配，不能直接保存。重复原文需多复制上下文，使来源唯一。列表最大32个片段。未添加片段的旧笔记无需补标即可参加城市查询，但不会参加区县查询。

## 数据与接口

迁移`20261009_01`在`knowledge_entries`追加JSON列`sections`，旧记录默认空数组，保留原正文。迁移已在临时SQLite验证旧版→新版、降级→再次升级，未操作线上数据库。

```json
{
  "category": "travel_guide",
  "title": "福州攻略",
  "body": "长乐：清淡海鲜。\n鼓楼：三坊七巷散步。",
  "city_code": "350100",
  "city_name": "福州市",
  "sections": [
    {"district_code": "350112", "category": "food_guide", "text": "长乐：清淡海鲜。"},
    {"district_code": "350102", "category": "attraction_guide", "text": "鼓楼：三坊七巷散步。"}
  ]
}
```

创建、读取、修改接口均支持sections；新增需登录的`GET /api/v1/agent/knowledge/districts?city_code=350100`，返回该城市区县编码与名称，供Android选择。修改正文时旧片段失效会返回422，不静默删除用户标注。
