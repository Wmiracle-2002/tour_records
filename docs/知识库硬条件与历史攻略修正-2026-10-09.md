# 知识库硬条件与历史攻略修正

日期：2026-10-09。状态：本地实现及离线验收完成，未部署、未提交Git。

## 用户确认的口径

- 地点和明确饮食要求必须同时满足，不能只命中其中一个。
- 历史攻略覆盖所有符合查询条件的个人笔记，不限定为“旧攻略”标签或travel_guide类别。具体问美食、景点时仍保留类别限制。
- 本轮先处理这两项，不扩大到否定语义、长文切片和饮食同义词修复。

## 排查与修改

原检索将关键词分数相加，只要一个词命中就可进入候选。因此“夫子庙清淡餐食”会同时召回夫子庙辣火锅和玄武湖清淡餐食。

`server/app/agent/knowledge.py`改为所有非空检索词均有匹配证据才入选，再按分数排序。去掉原先只取前4个词及每词前40字符的隐式截断，避免遗漏条件。当前为字面匹配，不声称具备完整语义理解。

有sections的笔记只用当前片段正文提供匹配依据；整篇标题、标签不能为另一片段补足条件。没有sections的旧笔记仍可在标题、标签和正文中匹配。城市、区县、账号、类别硬筛选保持生效，无匹配不回退全城。

历史攻略入口原本kind=None时已不限制类别，符合本次确认。修正的是KR11的评测参考标准：原仅认笔记11，现认可同地点笔记2、6、7、11、13，category置空。没有把旧价格当作当前事实，也没有删除旧参考文件。候选覆盖所有符合条件的笔记，传给模型的上下文仍最多5个片段、总800字符，不等于一次返回全部原文。

注意：当前Agent入口将preferences直接作为检索词传入，因此这项调整采用严格交集，不会自动区分其中的软偏好、选择性偏好或同义词。复杂偏好可能导致少召回；本轮样例不代表这类输入已经充分覆盖。
