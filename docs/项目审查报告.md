# 项目审查报告

日期：2026-09-28。审查以当前 `fix/agent` 工作树为准，包含尚未提交的 Phase 16 流式输出改动。范围包括 Android 旅行与聊天入口、服务端认证/旅行 API、Agent 图和工具边界、记忆与 SSE、配置/部署及现有自动化测试。本文是代码与测试审查，不代表已覆盖所有真实设备和第三方服务故障。

## 结论

未发现阻止本地构建与自动化回归的缺陷。发现并修正 3 个过期的 Android 仪器测试断言；原先失败反映的是测试输入/期望和当前界面、照片 ID 不一致，并非照片接口或登录流程的新故障。历史文档散落在根目录、README 混有已过时的里程碑描述，已集中到 `docs/` 并重写根目录入口。

项目已经具备记录 CRUD、云端同步、结构化 Agent、会话记忆、严格工具校验及阶段 SSE 进度。**“没有问题”只能限定为本轮自动化回归通过**；真实手机流式问答、弱网和最低 Android 版本仍需验证，Phase 17 个人知识库尚未开发。

后续用户实测又发现两项缺陷：复合行政区名“福州长乐”未被 POI 参数校验接受、需求提取可能缩成“福州”；失败后再次发送可能使 Android 临时消息 ID 与服务端历史消息 ID 冲突。已增加失败用例并修复；地点修复已部署，真机复测状态以 [开发日志](开发日志.md) 最新条目为准。

## 尚需验收或后续处理

1. **真实手机与真实 LLM（优先）**：服务端 SSE 路由、认证边界及本地真实 HTTP 提前到达已验证，但尚无真实账号手机发送消息的完整链路证据。需检查阶段先到、完整回答可回看、断网重试和 `request_id` 日志关联。
2. **外部服务和设备矩阵**：真实 COS 凭据、长时间/弱网同步、第二台设备及 Android API 24 最低版本尚未完成系统回归。自动化模拟结果不能替代这些验证。
3. **流式能力边界**：`stage` 是实时进度；多日规划按完整一天解析、校验、发送 `preview`，最后用整份行程的校验结果替换预览。短问答和单日行程仍可能集中显示。真实手机逐日体验尚未验收。
4. **云端多步写入一致性**：Android 云端创建/编辑记录可能依次调用 Trip、Record、图片接口。当前部分失败路径有补偿删除，但不同请求之间无法像单个数据库事务那样原子提交；第三方 COS 或网络中断时仍应做专项故障注入与人工恢复验证。这是架构层面的残余风险，当前回归未证明它会在正常路径出错。
5. **后续功能**：个人收藏攻略/笔记知识库只在 [Phase 17 计划](Agent开发计划.md) 中；当前 Agent 不会引用未实现的知识库。

本轮将三个已验证的地点相关 Python 文件及六个逐日预览文件分批备份、部署到服务器，路径见开发日志；服务器 `.env` 和数据库未改。本地代码、文档尚未提交或推送 Git。
