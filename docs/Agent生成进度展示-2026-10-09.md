# Agent生成进度展示

日期：2026-10-09。

## 行为

发送后在助手消息位置显示临时卡片：执行阶段、实际完成/简化/失败状态和已用秒数。正文出现后收成一行“正在输出回答”，最终回答加载完成后自动隐藏；失败保留失败位置，输入内容可重试，关闭错误后移除进度。新请求清空上次进度。

阶段来自服务端真实stage_started/stage_completed事件，只转发公开阶段名和状态，不显示提示词、工具参数、供应商错误或内部推理。不推算完成百分比，不额外调用LLM，不能因此宣称实际耗时缩短。

旧服务端仅有message时仍兼容展示“进行中”，不会猜测成功。新增stage/status字段对旧客户端兼容。当前页面离开后恢复使用既有ViewModel及底部导航状态；不承诺进程被系统杀死后继续计时。

## 验证

- 新服务端测试先因缺stage字段失败，再验证公开开始、成功、简化、失败状态及私有细节不外露。
- SSE接口8个测试通过，包含真实回环HTTP中完成前进度可见、逐日预览和断开行为。
- Android单元测试覆盖阶段结果、完成清空、失败保留、旧事件兼容及原有输入草稿、逐字显示、重试行为；测试与APK构建通过。
- 后续模拟器验收14个智能规划界面测试通过：覆盖完成前展示、正文收起、完成隐藏、较长历史滚动、底部页面切换及草稿保留。真机及线上服务同步仍未执行。
- 模拟器定位到LazyColumn移除临时项后旧进度及预览节点残留；固定进度项并在完成时明确清空内容后通过，未放宽隐藏要求。旧输入仅streamingStage时增加兼容显示。
- ReAct的stage_completed是查询决策完成，公开显示为“选择查询方式”，避免误称资料查询完成。
- 串行SSE复测8通过；并行模拟器测试期间断连清理用例曾观察到pending等待超时，保留失败记录，串行复跑通过，未修改等待阈值，不认定为新增API逻辑故障。
- 未调用真实LLM，不将模拟器和固定Runtime测试称为真实模型线上验收。

## 使用

构建使用`-PfootmarksApiBaseUrl=https://www.cq-footmark.online/`。手机测试南京三日游：生成时检查进度及秒数，正文出现后查看收起，完成后仅保留回答；请求期间输入下一条消息不应被清空，切换底部页面后回来应保持请求状态。

服务端需更新`server/app/api/agent.py`并重启应用才能返回完成状态；旧服务端仍能显示当前阶段。地图开发在当前版本提交推送之后进行，详见[地图方案](旅行足迹地图开发方案.md)。
