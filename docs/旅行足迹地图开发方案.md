# 旅行足迹地图开发方案

日期：2026-10-09。执行顺序：进度功能验收 → 提交推送当前版本 → 开发地图视图 → 地图验收。

当前状态：进度及既有评测版本已推送fix/agent（33e17fc，补充进度修复c4607bc）；地图首版及手势缩放已实现并通过相关验收。执行记录见[地图实现与验收](旅行足迹地图实现与验收-2026-10-09.md)。

## 目标与交互

记录页增加“列表／地图”切换，保留现有三个底部导航入口及旅行CRUD。地图用于按地区浏览记录，不增加导航、定位、路线或景点坐标功能。

1. 全国视图显示省级轮廓，有旅行记录的省份高亮。
2. 点击省份显示省内地级市轮廓与出行次数，提供返回全国按钮。
3. 点击城市，在地图下面显示该城市的旅行列表，日期倒序；点击旅行进入原详情页。
4. 没去过的城市可点击，显示无记录提示；同城多次旅行独立展示。
5. 直辖市点击省级区域直接展示该市记录，不展开区县。省直管县级市沿用既有可选城市例外，不丢失记录。

## 技术方案

采用Compose Canvas绘制行政区轮廓，加载本地GeoJSON，按层级切换后自动适配视口。按用户补充要求增加双指缩放与拖动（1～12倍），提供放大、缩小、复位按钮；上海等小区域可放大后点击。绘制与命中使用同一变换，切换行政区重置视口，不接入道路底图或卫星图。

边界来源为阿里云DataV.GeoAtlas官方公开数据：

- 官方入口：https://datav.aliyun.com/portal/school/atlas/area_selector
- 全国省级边界：https://geo.datav.aliyun.com/areas_v3/bound/100000_full.json
- 省内下级边界使用同一来源的省级编码文件，下载时验证实际行政级别、父级、Polygon/MultiPolygon结构，不把区县默认当作地级市。

将经过结构校验的数据随APK打包，页面只按需读取当前层级；保留来源和获取日期。当前已只读验证全国数据可下载，35个Feature、约583KB。无需新Key或修改服务器配置；若省市编码不匹配，明确保留提示，不能按模糊名字错误归属。展示范围沿用来源数据，不自行简化删除边界或附属区域。

复用现有Room中的TripWithCityAndRecords与CityEntity.cityCode/provinceCode聚合，地图和列表使用同一账户缓存和同一数据流。城市代码以现有行政区目录为准，省级代码规范为6位；空代码、无法映射的历史记录仍留在列表，并显示地图未匹配数量。

边界数据是公共静态资源；旅行计数和记录不写入公共资源、磁盘地图文件或外部请求。无需新增业务数据库表、后端接口或LLM调用。

## 风险和范围

- 边界数据和项目2023区划目录可能有版本差异，以编码精确匹配，不自动合并名字近似的区域。
- Canvas需要正确处理MultiPolygon和内环，点击命中必须与绘制使用同一投影。
- 静态数据会增加APK体积，记录实际增量；首版优先离线可用和实现简单。
- 下载、测试或映射失败必须明确报告，不以示意方块或虚构轮廓冒充真实地图。
