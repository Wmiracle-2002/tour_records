# 用户注册、登录与账号管理开发计划

状态：A～E 已实现；F 已完成服务器备份、部署、旧账号迁移、公开注册与额度联调，真机跨账号验收待完成。更新：2026-10-01。

## 1. 目标与已定规则

- 面向公众开放用户名、密码注册；用户名区分大小写，`ccqq` 与 `Ccqq` 是不同账号。同一账号可以在多台 Android 设备登录，看到同一份云端数据。
- 注册后的旅行、照片元数据、对话及记忆、偏好、收藏都归属服务端用户 ID。旧版纯本地记录和旧版无账号归属的 Room 缓存可在升级时清除；后续不再创建匿名本地旅行。
- Android 提供注册、登录、退出、切换账号和自行注销账号。注册成功后进入该账号；“保持登录”由用户选择，保存可撤销的登录令牌，不在 App 内保存密码。用户名可记住；未保持登录时下次需重新输入密码。离线时只显示上次已登录账号的缓存。
- `admin` 是独立的管理员账号，也从 Android 登录。管理员界面提供账号管理、应用数据管理和智能规划用量管理；公开注册永远只能创建普通账号。管理员不使用普通旅行/Agent 页面。
- 智能规划额度按北京时间自然月重置，管理员可设置新账号默认上限与单个账号上限。统计本账号所有 LLM 调用的输入、输出 token，包括重试和记忆压缩；JSON 与 SSE 接口共用额度校验。
- 当前旧账号的云端内容迁往普通账号 `ccqq`，核对完成后删除旧账号。`admin` 不承接这些内容。密码、Token Secret 和其他密钥不得写入本文、代码、Git、日志或部署命令历史；正式设置时使用受保护的交互输入，并更换曾在聊天中出现过的密码。

## 2. 当前实现与改造原因

| 现状 | 需要增加 |
| --- | --- |
| `users` 有唯一用户名和密码哈希；业务表已按 `user_id` 鉴权 | 公开注册、角色/状态、账号会话及管理员鉴权 |
| `app.bootstrap` 只初始化一个账号，无注册、退出或找回密码 | 独立的管理员初始化与普通用户注册/重置流程 |
| Android 仅保存 Access/Refresh Token；Room Trip/Record 没有账号归属 | 保持登录、退出/切换时清理内存状态、按账号隔离 Room 缓存 |
| `GET /trips` 每次返回完整旅行和照片签名 URL，客户端全量对账 | 首次全量快照，后续只取变更与删除事件；照片按需取有效访问地址 |
| LLM 客户端未持久化上游 `usage`；流式响应忽略可能仅含用量的末尾事件 | 实际用量账本、预留额度、并发控制、流式用量解析及保守兜底 |

现有 `/api/v1/trips` 保留给旧客户端；新增同步接口供新版使用。数据归属一律取已验证的服务端身份，客户端传入的 `user_id` 不能决定读写目标。

截至本文编写时，工作区仍有前一阶段的未提交修改。实施前应先记录并核对代码基线，避免把注册改造与既有变更混在同一次回归或部署中。

## 3. 注册与登录契约

1. `POST /api/v1/auth/register` 接收用户名和密码。用户名去首尾空格后长度 3～32，只允许英文字母、数字和下划线；大小写原样保存并按大小写判重，`admin` 的任意大小写写法均为保留名。密码长度 12～128，不在响应和日志中回显。重复用户名返回明确的 409；非法输入返回 422。
2. 注册只创建 `role=user`、`status=active` 的账号，不接受角色、额度、用户 ID 等客户端提交字段。用户名唯一由数据库约束最终保证，处理并发注册冲突。
3. 注册成功后自动登录当前设备。“保持登录”打开时，安全保存 Refresh Token 并在下次启动续期；关闭时令牌只留在当前运行期，关闭 App 后需重新登录。“记住账号”只记用户名，不保存密码。
4. 继续支持现有登录和 Access Token；增加服务端会话标识和 Refresh Token 轮换/撤销。退出当前设备、管理员重置密码、停用/注销账号后，旧刷新令牌不可再使用。升级前的旧令牌允许失效并要求重新登录，不改变服务端旅行数据。
5. 没有邮箱/短信校验。忘记密码由管理员在 Android 管理界面重置为一次性临时密码；用户首次使用临时密码后修改密码。管理员不能读取任何账号原密码。
6. 公开入口设置注册与登录的 IP/用户名频率限制、请求体长度限制；达到限制返回 429。管理员角色只能由服务端一次性初始化，不能通过注册或普通资料修改接口获得。

## 4. Android 账号与缓存

- 未登录展示登录/注册入口；注册与登录共用校验规则。普通账号进入现有三个底部页面，管理员进入独立的账号/数据管理导航。
- Room Trip 增加账号归属；相关 Record 通过 Trip 归属，所有列表、详情、统计、编辑、删除查询必须限定当前账号。切换账号时先取消旧账号网络任务、清空当前页面状态，再激活目标账号的缓存；旧账号缓存可保留但不可显示给新账号。
- 升级时清理旧版无账号归属的 Room 旅行、记录及旧版本地照片文件；不触碰服务端和 COS。升级/清理为一次性操作，失败时不得把旧数据错误地挂到新用户 ID。注销账号后删除本机该账号缓存及令牌。
- 同一账号再次登录先显示其缓存，然后增量同步。新设备或无游标的账号获取一次完整快照。同步中断时保持已提交游标，重试应幂等，不出现重复旅行。
- 退出/切换与登录并发时，旧响应不得写入新账号缓存；刷新令牌过期时保留该账号缓存但停止云端写入，提示重新登录。

## 5. 增量同步契约

- 服务端增加按账号排序的旅行变更事件。Trip/Record/照片创建、修改、删除时，在同一数据库事务中记录受影响的 Trip；删除 Trip 写删除事件。事件包含递增序号、用户 ID、Trip ID、事件类型，不在同步游标里暴露其他用户数据。
- `GET /api/v1/sync/trips` 首次分页返回当前账号完整快照及游标；后续携带游标，只返回变更 Trip 的最新完整详情和删除 ID。分页、断点续传与并发写入必须不漏事件；客户端在 Room 事务提交成功后才保存新游标。
- 照片缓存以稳定图片 ID 为键；照片字节只在打开时按需下载。COS 签名 URL 到期后只更新访问地址，不能把已过期 URL 当作永久缓存标识。图片内容变更使用新 ID 或版本号，以便失效旧缓存。
- 旧 `/trips` 全量接口暂时保留；新同步接口完成后，登录/刷新不再走旧全量请求。用户主动下拉刷新也只拉增量。

## 6. 管理员 Android 功能与权限

- 管理员登录后可分页查找账号，查看状态、创建时间、当月用量及额度；可创建、停用/启用、重置密码、删除普通账号和设置其额度。不能删除或降权最后一个管理员账号。
- “数据管理”按用户查看和增删改旅行、子记录/照片、会话、偏好和收藏。复用业务层校验、COS 删除逻辑与变更事件；不提供原始 SQL 编辑。Agent 记忆摘要/工具结果作为派生数据随会话清理，不提供逐表随意编辑。
- 所有管理员 API 在服务端验证 `role=admin`，操作明确指向目标用户 ID；普通用户无权调用。审计记录包含管理员 ID、目标用户 ID、动作、对象 ID、时间、请求 ID 和结果，不记录密码、令牌、聊天正文或照片内容。
- `admin` 本身只显示管理页面；账号状态变化及数据修改要实时影响普通用户的鉴权、同步和额度。

## 7. 智能规划月度额度

- 使用北京时间月份 `YYYY-MM` 作为周期，不依赖定时清零任务。当前全站默认额度为每月 50,000 token；管理员可修改默认额度并设置单账号覆盖值。普通用户可在个人中心查看当月上限、已用和剩余额度。
- 以服务商返回的本次输入/输出 token 为优先计量来源；流式请求需要解析末尾用量事件并验证所接 LLM 服务的兼容行为。没有可靠用量时按调用前预留额度保守计费，不能悄悄把“估算值”展示为实际用量。
- 每次上游 LLM 请求前按该阶段最大 token 预算原子预留额度；完成后结算实际用量，释放未使用的预留。并发请求、超时、重试和用户中断都不能超额或重复入账。已实际消耗的失败调用仍计入用量；尚未发给上游的预留可释放。
- 达上限时拒绝新的 LLM 阶段，返回稳定错误码与额度/下次重置时间；不清空用户输入框或已保存的对话。无需 LLM 的旅行记录查询是否仍可用，以实际调用链为准，不能因额度不足却暗中继续调用模型。
- 同时限制公开注册及上传请求频率，并保留现有单条照片大小/数量限制。公开注册上线前必须设置每账号照片存储总量上限，并在上传前按已有元数据原子检查；管理员界面显示各账号用量，防止不限量注册和上传占满 COS。

## 8. 账号注销与旧账号迁移

- 普通用户自行注销需再次输入密码并确认。服务端先停用账号、撤销会话，再删除关联 COS 对象和 SQLite 数据；外部对象清理失败时保留可重试状态，不报告“已删除”。本机成功后清除该账号令牌、Room 缓存与图片缓存。管理员删除普通用户走相同清理流程。备份文件按服务器备份保留策略另行管理，不将“在线删除”误称为备份即时清除。
- 迁移前备份并校验线上 SQLite，列出旧账号的 Trip/Record/照片、会话及记忆、偏好、知识条目数量和 COS 对象清单。确认目标 `ccqq` 身份；若已有同名账号或偏好类别冲突则中止，不覆盖数据。
- 在事务内将旧账号下的旅行、会话、偏好和收藏改属目标用户；Record、图片、消息、摘要和工具结果保留原有父级与 ID。COS 对象键保持不变，不重复下载/上传照片。迁移后逐项核对数量与目标账号可读性，撤销旧会话，再删除旧账号；失败时可用备份恢复。
- `admin` 账号通过服务器受保护的初始化步骤单独创建，`ccqq` 为普通账号。账号密码通过安全的交互输入设置，不在迁移脚本、文档、Git 或日志中出现。

## 9. 实施顺序与逐步验收

| 步骤 | 实现 | 回归与验收 |
| --- | --- | --- |
| A. 数据与身份（本地完成） | 角色/状态、会话、密码重置、账号字段迁移；保留旧账号数据 | 认证与迁移测试通过；临时密码强制修改，旧会话撤销 |
| B. 注册与公开入口（本地完成） | 注册、重复用户名、频率限制、登录/退出/自注销 API；默认关闭注册 | 边界、越权、旧数据及照片容量测试通过；全量回归通过 |
| C. 额度（代码与模拟测试完成） | LLM JSON/SSE 用量采集、月度账本、预留/结算、管理员调额 | 模拟用量测试通过；真实上游小额度联调待 F 阶段 |
| D. 增量同步（代码与模拟测试完成） | 变更事件、快照/游标/删除事件、按账号 Room 缓存、图片签名地址刷新 | 服务端与模拟器回归通过；两台真实设备待 F 阶段 |
| E. Android（模拟器完成） | 注册/登录/保持登录、普通用户注销与额度页、管理员账号/数据管理 | JVM 与模拟器全量通过；真机和新版 APK 仍需 F 阶段 |
| F. 迁移上线（真机验收待完成） | 已完成线上备份、创建管理员和 `ccqq`、旧数据迁移核对，公开注册与每月 50,000 token 默认配额已启用 | 服务器健康、公开 HTTPS 注册、账号与角色隔离、COS 照片、真实模型额度、增量同步联调已通过；真机跨账号验收待完成 |

每一步完成后先运行对应自动化测试和受影响功能回归，再进入下一步。生产部署先备份、验证迁移和回滚路径；公开注册与管理员入口在权限、额度、同步和资源限制通过线上验收前不对外开放。
