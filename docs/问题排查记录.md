# 问题排查记录

更新日期：2026-10-08。本文汇总开发过程中已定位的主要故障；日期是排查或修改日期，不代表所有问题当天完成了真机验收。具体实现和当时的测试数字见[开发日志](开发日志.md)。

## 排查方法

1. 固定触发步骤、提问文本、客户端版本和访问地址，区分真机、模拟器、本地服务端与线上服务端。
2. 先看 Android 异常或 HTTP 状态码；用响应的 `X-Request-ID` 对照 Nginx、FastAPI、Agent 阶段和工具日志。`404`、`401`、`502`、`504` 的含义不同，不能只看聊天页提示。
3. 比对部署中的代码版本、环境配置项是否存在和请求参数；不把密钥、完整 Prompt、个人数据写入排查文档。
4. 用最小用例复现，修改后跑定向测试、相关全量回归；涉及网络或布局的，再用服务器或设备验证。自动化通过不等于真机或线上已经验收。

## 最近一次导航闪退的排查过程（2026-10-03）

1. 最初描述是“发消息后切换页面闪退”，先验证聊天状态和页面切换，未据此确定原因。
2. 根据后续补充，把步骤缩小为“个人中心→顶部账号卡→底部任意导航”。在模拟器重放并读取 `adb logcat`，异常指向 `MainNavigation` 的 `getBackStackEntry("profile")`。
3. 检查导航栈与组合重绘时机，确认子页面可切 Tab，且仍依赖已被移除的 Profile 栈项，导致取栈失败。
4. 修改 `MainActivity`，仅在三个顶层页面显示底部导航；修改 `MainNavigation`，通过 `remember(entry)` 保存子页面依赖的 Profile 栈项。
5. 增加 `AccountNavigationTest`，验证登录页隐藏底部导航、返回后可以继续切换页面。完整模拟器测试 61 项通过。登录后账号管理页和用户手机同样路径仍需最终复验。

## 连接与认证问题的判别

- 手机浏览器也无法打开 `/api/v1/health` 时，先查网络、DNS、TLS 和代理可达性；仅凭 `Connection reset` 无法断定是密码或业务代码错误。
- 健康接口可达，但登录返回 `401` 时，继续查账号名大小写、临时密码及账号状态。2026-10-01 部署使用随机一次性密码，旧聊天中指定的密码不能当作服务器实际密码；密码值不写入本记录。
- 业务接口先 `401`，随后 `/auth/refresh` 为 `200`，再重试成功，是 Access Token 过期后的刷新流程；只有刷新或最终重试失败才继续按认证故障排查。
- `/`、`/favicon.ico`、`/wp-admin/...` 等请求的 `404` 不代表 Agent 故障；应按用户实际请求的接口和请求 ID 判断。
